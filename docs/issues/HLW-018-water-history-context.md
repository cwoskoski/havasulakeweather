# HLW-018: "Compared to history" context on /water (percentile + multi-year trend)

- **PR:** —

## Summary

Now that ~90 years of daily storage & releases are stored (HLW-017), put that record to
work on the `/water` page: tell a visitor whether today is **high or low compared to
history for this time of year**, not just vs. the recent season. Real example (today):
Lake Havasu storage **541,741 af = 7th percentile of 88 past Augusts** (lower than ~93%),
and the Davis release is the **lowest August on record**.

## Motivation / grounding (real, from our stored data)

- Havasu **August** storage, 88 yrs (1939–2026): current 541,741 af → **7th pctile**;
  range 120,000 (lowest yr) … median 580,349 … 675,000 (highest).
- Davis **August** release, 78 yrs: current 4,429 cfs → **0th pctile** (lowest on record).

These are strong, legible statements — exactly the "is this normal?" question locals ask.

## Scope

### v1 — "compared to history" callout (core)
- **Precompute stats** (`ingest/scripts/build-history-stats.mjs`, committed script): read the
  backfilled `WATER#DAILY` record from DynamoDB, and for each **month** compute the
  distribution of **per-year monthly-median** values for Havasu storage, Mohave storage,
  Davis release, Parker release → `{ p10, median, p90, min, max, nYears, sinceYear }` plus
  the full per-year series (for the sparkline). Emit `ingest/data/water-history.json`
  (static, like `water-normals.json`; regenerate occasionally — the distribution barely
  moves). **Bonus:** regenerate the HLW-014 release bands from the full 90-yr record here
  too (currently a ~7yr sample), so the low/normal/high bands get 90-yr-accurate.
- **`/api/water`** adds a `history` block to `lake` (and optionally `inflow`/`outflow`):
  `{ percentile, nYears, sinceYear, monthMedian, monthLo, monthHi }`, computed by ranking
  the current value against that month's per-year distribution. Cheap (static lookup).
- **`/water` page**: a "vs history" line/badge on the Lake Havasu card, e.g.
  *"Storage is lower than 93% of past Augusts (88 yrs on record)."* Optionally a smaller
  note on the release rows. SW bump.

### v2 — multi-year trend sparkline (stretch)
- A small **decades sparkline** on the card: per-year same-month storage (1940s→now) with
  the current year highlighted, so the long arc (fill, droughts, recovery) is visible at a
  glance. Reuses the per-year series already emitted in v1's stats file.

## Design decisions / caveats

- **Framing = percentile-of-history for the current month.** Compare today's value to the
  per-year *monthly-median* distribution → "lower/higher than N% of past <month>s". Simple,
  honest, matches HLW-014's monthly frame.
- **Storage, not elevation.** We only have datum-clean storage history (HLW-017), and it's
  the acre-feet framing we already lead with. No elevation history involved.
- **Exclude the reservoir fill period.** Havasu filled 1938–~1940 and Mohave ~1950–~1954;
  those early years aren't "drought lows." Pick a sensible `sinceYear` per reservoir
  (Havasu ~1945, Mohave ~1955) so "record low/high" claims are meaningful, and label the
  callout with the actual `nYears`/`sinceYear` used.
- **Static stats file**, regenerated by the committed script — no request-time scan, no new
  scheduled job. (Could later add a low-frequency refresh if we want it fully automatic.)

## Acceptance criteria

- [ ] `build-history-stats.mjs` produces `water-history.json` (monthly per-year distributions
      + per-year series) from the stored record; fill-period start years applied.
- [ ] `/api/water` returns a `history` block with the current value's percentile for the month.
- [ ] `/water` shows a clear "vs history" callout (real: "lower than ~93% of past Augusts").
- [ ] (v2, optional) decades sparkline on the card.
- [ ] Mock/preview path (`?mockWater=`) exercises the callout; local verify + Chad preview.
- [ ] No new secrets; no request-time DynamoDB scan.

## Out of scope

- Backfilling / new data sources (done in HLW-017).
- Historical elevation, day-of-year smoothing (possible later refinement).
